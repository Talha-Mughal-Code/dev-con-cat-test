# Super Pixel Spec

The Super Pixel is the one snippet a buyer embeds — the TrustedForm analogy is
deliberate. `examples/super-pixel.js` is a **reference implementation** that runs
in local simulation mode so the example landing page is demoable with no backend.
Your job is to make it real against your Rails app.

## What the pixel must do
1. **Boot a capture session on page load** and record page context (URL,
   referrer, user-agent, timestamp) and fire a **site-visit beacon** so the
   backend can later compare the visit IP to the submit IP.
2. **Instrument the lead form** — stream field focus/blur/change so activity can
   be shown live.
3. **On submit**, POST the captured lead to your ingestion endpoint.
4. **Subscribe to verification activity** for that lead and surface each
   detection layer's result as it lands, then a final verdict.

## Suggested HTTP contract (you may change it — document if you do)
```
POST {endpoint}/visit
  { session_id, pixel_id, page_url, referrer, started_at }
  -> 202 Accepted

POST {endpoint}/leads
  { session_id, pixel_id, submitted_at, form_dwell_ms, fields: {first_name,...} }
  -> 201 { lead_id: "L-..." }

# then stream activity for that lead back to the page, e.g.
GET {endpoint}/leads/:lead_id/activity        (SSE)
  event: layer_result   data: { layer, verdict, detail }
  event: final_verdict  data: { verdict, score, reasons }
```

## Real-time transport — your decision
The example page consumes an **event stream** via `SuperPixel.onActivity(cb)`.
In simulation the pixel fakes those events. You must replace the simulation so
the events are driven by **real** verification results from your backend. Pick
SSE, WebSocket, ActionCable, or short-polling and **justify the trade-off** in
`SOLUTION.md` (latency, connection count, complexity, reconnection).

## The live landing page — the "proof it works" deliverable
`examples/landing-page.html` already renders a live activity panel. Wire it to
your app so that, as a real form is filled and submitted, the panel shows the
**actual** layer-by-layer verdicts your engine produced — not the simulation.
This is how you demonstrate, end to end, that the pixel catches what it claims.

## Pixel management
The snippet's `data-pixel-id` and `data-endpoint` must be **generated by your
app** when an account admin creates a pixel — including producing the exact
copy-paste snippet text for the buyer. A pixel is scoped to one account and to
that account's enabled modules; a lead captured by a pixel inherits that
account's isolation and credit accounting.

## Security things worth a sentence in SOLUTION.md
- How do you stop someone POSTing leads to another account's pixel?
- What stops the pixel endpoint from being abused/replayed?
- What lives client-side (it's public) vs. server-side?
